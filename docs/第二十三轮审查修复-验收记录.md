## 3 关键口径

1. **云端事务「先读后写」**：`commitEventChange` 虽已改用 `event.revision` 校验，但因 `school-repository` 的范围 `set` 内部会先 `getById` 校验归属，仍须在全部 `set` 之前预读新建 `writes` 以命中事务读缓存，保证所有 `get` 严格早于 `set`。
2. **首页加载失败与跨校只读空聚合区分**：`loadSchoolHomeView` 对服务端明确业务拒绝（如跨校浏览北航返回 `ok: false`）标记 `err.refused = true` 并返回真实空聚合；仅在网络/云函数异常导致整页无数据时抛出，阻止写入 5 分钟空缓存。
3. **`isMock` 实例化求值与 `onLoad` 同步**：页面在 `data` 初值仍调用 `isMockNow()`（不解构模块期常量），并在 `onLoad`/`attached` 中再次同步 `isMock: isMockNow()`，兼顾未调 `onLoad` 的装配测试与运行期切换数据源的真机路径。

## 4 踩坑与纠正

- **`commitEventChange` 去掉 `writes` 预读后 `football-f23` 变红**：原因如 §3 第 1 条，范围 `set` 的归属校验在事务内触发 `get`，导致写后读交错。恢复新建 `writes` 预读并保留 `event.revision` 校验后恢复全绿。
- **`exchange-service` `reviewEntrants` 误用 `repo.schoolMembers.listByIds`**：`reviewEntrants` 传入的是顶层 `repo` 而非 `forScope`，顶层 `schoolMembers` 无 `listByIds`（已由 `exchange-cloud` / `exchange-service` 用例拦截）。改为 `Promise.all(memberIds.map(id => repo.schoolMembers.getById(id)))` + `users.listByIds`。
- **内存分页 `limit: 0` 与 `limit: 100` 边界**：`Number(limit) || 20` 会把 `limit: 0` 变成 20，而 `Math.min(..., 99)` 使 `page.test.js` 期望 `100` 条的本地用例断言 `99 !== 100`。`memoryMatchPage` 按 `limit == null ? 20 : Math.max(0, Math.min(raw, 100))` 兼顾两端契约。
