## 3 关键口径

- `match-list-query` 内存端仍夹 100：演示台账与 `page.test.js` 依赖一次取满 100 条；云端 `listPage` 因多取 1 条判 `hasMore` 夹 99。生产调用最大 20，该边界差异只影响演示/测试，保留并注释。
- 运动会签表草稿守卫对管理员放行：管理员需要在筹备期检查签表；普通会员仍被拒绝。
- 三面板的请求序号只作废**在途**请求，不阻止组件重新挂载后的首次装载。

## 4 踩坑与纠正

- `page.test.js` 的录入台账依赖一次取满 100 条；把内存上限改成 99 会让 `beforeRecords.length` 少一条。最终保留 100 并写明与云端的差异。
- 运动会签表草稿守卫最初对所有身份生效，`meet-config-extra` / `meet-progression` 的管理员用例变红；改为 `!canManageMeet(ctx)` 才拒绝。
- 足球直红用例把 `directRed` 标成 `full` 后，校验要求所有球员都填 0/1；补齐全队 0 再置 1。
- 新增服务端文件改动后必须先 `npm run sync:cloud`，否则 `cloud-lib-sync` 变红。
