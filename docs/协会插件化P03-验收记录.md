## 1. 本批改动

1. **服务端插件真正接线**：`team-event-service.js` 新增 8 处 `getSportAdapterFor` 按协会/赛事取运动能力（权限、赛程人源、场次初始扩展、版本分派等）；模块加载期对全部导出 action 动态包装，按 `ctx.association` 实时查服务端插件做 override，兼容动态插件与测试切换。
   - **无递归风险**：football-match-service / football-schedule-service 无同类包装；插件 actions 引用的是这两个服务的原始函数，不回指被包装的 team-event-service。
2. **单场运动扩展字段统一**：`footballDraft/footballPublished/footballLineups/footballAudit/footballRequests/footballSchedule*` 全量改为 `sport*`，覆盖服务端、shared 契约、索引声明与 demo 种子；`src/` 生产代码与 `config/db-indexes.json` 零旧字段残留。
3. **默认钩子工厂**：新增 `createSportAdapter`，为可选钩子提供显式默认实现并统一执行契约校验；篮球适配器改用它，P-02 的 5 处手写 stub 收敛为统一默认。
4. **新增 3 条静态守卫**：`createSportAdapter` 默认实现通过契约、team-event-service 无运动硬编码与旧足球模块直连、src 与索引无旧 `football*` 单场字段残留。

## 2. 关键口径

- **字段改名无需迁移脚本**：规划 §1 / §7.1 明确"首次上线前无历史数据、无线上旧客户端"，当前处于干净清理窗口，故未写回填脚本；**若日后已有线上数据，任何同类字段改名必须补 schemaVersion + 读端回退 + 幂等回填**。
- **默认钩子仍是空实现**：`validateBeforeSettle` 恒 true 等由工厂提供，但已显式定位为"可选钩子默认"，不再是伪装成完整实现的 stub；新运动插件按需覆写。
- **排球仍未做**：`team-event-service.js` 状态机拆分与排球 `volleyball6` 适配器按规划属"上线后按触发条件再做"，本批只收口篮球/足球两个已立项运动。
