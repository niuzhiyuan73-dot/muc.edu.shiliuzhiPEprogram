## 3. 关键口径

1. **运动会 `contentRevision` 写回分流**：高频写路径（录分、提交分、报名、派裁判）只推进单项目 `sportsMeetEvents[eventKey].revision`，不再争用同一届次 `sportsMeets` 文档；仅正式发布（`bumpMeet: true`）与赛程编辑保留届次级版本号。
2. **团队赛事单栅栏覆盖边界**：除高频逐球计分 `updateTeamLiveScore` 外，所有修改 `teamMatches` / `teamEventEntries` 的事务均推进 `teamEvents.revision`；`commitEventChange` 最高支持 200 场（超过 200 场写前返回 `TEAM_BATCH_LIMIT`）。
3. **批大小校准优先级**：`BATCH_JOB_MAX_OPS` 是全局校准预算，与业务接入点自带的天花板（如派裁判 `JUDGE_OPERATION_BUDGET=90`）取**较小值**。环境变量只能收紧、不能抬升业务天花板——T-06 真云实测若发现平台更严，设一次环境变量即可下调全部接入点，无需改业务代码。

## 4. 踩坑与纠正

- **`association-group-service.js` 空小组删组尾批边界**：成员已移空的小组 `page.rows` 为空数组，接入 `runVersionedBatchJob` 后若直接传空数组不会进入 `runBatch`，导致 `cleanupPending` 未置 `false`。改为 `page.rows.length > 0 ? page.rows : [null]` 并在回调过滤 `null`，保证空页尾批仍执行收尾。
- **`meet-schedule-service.js` 跨批中断统计**：`runVersionedBatchJob` 返回 `ok: false` 时仍需将已完成子批的 `written`/`skipped` 累加到外层进度，否则 `tests/meet-judge-budget.test.js` 中断回归断言进度偏少。
- **验收复验发现环境变量在业务路径失效**：`resolveMaxOpsPerBatch` 原实现让显式 `maxOpsPerBatch` 直接短路环境变量，5 个接入点中 4 个硬编码预算（60/90）导致 `BATCH_JOB_MAX_OPS` 对业务路径无效。改为「业务天花板与环境变量取较小值」，并补 1 条穿透用例（含 60/90 两种天花板与业务路径实证），用例 3382 → 3383。
