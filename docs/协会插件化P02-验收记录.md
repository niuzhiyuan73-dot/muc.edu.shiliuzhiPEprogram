## 1. 目标与范围

把团队运动的差异从 `team-event-service` 的 `football11` / `basketball5` 二元分支中抽出来，形成：

- `src/shared/sports/contract.js`：六组契约校验与默认钩子工厂；
- `src/shared/sports/basketball/adapter.js`、`football/adapter.js`：两个已立项运动的插件；
- `src/shared/sports/registry.js`：按 `sportFormat` / 协会取适配器；
- `src/server/sports/registry.js`：服务端扩展动作白名单与动态分派；
- `src/shared/utils/team-sport-rules.js`：旧调用路径的兼容转发。

本切片**不包含**排球实现、状态机拆分与前端表单改造；这些分别属于后续切片。

## 2. 六组契约与实现名

| 契约组 | 实现字段 |
|---|---|
| `meta` | `sportFormat`、`sportKey`、`supportsLiveScore`、`supportsMatchData`、`supportsRedraw`、`allowsDraw`、`defaultMatchTimeFromEvent`、`defaultDurationMinutes`、`schedulePeopleSource` 等 |
| `rules` | `defaultPresetKey`、`defaultRules`、`normalizeRules`、`formatRules` |
| `permissions` | `canRecord`、`canSeePending`、`canSetLineup`、`canEditSchedule` |

| `standings` | `computeTable`、`adjustEliminationPlacements` |
| `view` | `eventFormMode`、`recordPageUrl`、`liveScorePageUrl`、`recordHintText`、`statColumns`、`profileStatColumns` |

设计文档 [团队运动-SportAdapter插件化设计方案](团队运动-SportAdapter插件化设计方案.md) 已同步为上述接口，不再保留 `validateDraft` / `resolveOutcome` / `aggregatePlayerStats` 等旧稿名称。

## 3. 实际改动

1. `contract.js`：`validateSportAdapter` 校验六组必需字段；`createSportAdapter` 为可选钩子提供默认实现。
2. 篮球插件：规则预设、实时计分能力、队长录分权限、7 项档案指标列。
3. 足球插件：赛后报告、严格名单校验、抽签仲裁、同轮淘汰并列名次、12 个服务端覆写动作。
4. `team-sport-rules.js` 兼容转发；`toLegacyStrategy` 保留旧扁平形状。
5. 服务端注册表按 `sportFormat` 注册插件，动作按白名单暴露。

## 5. 边界与已知限制

- 动态注册是单端模块实例：`src`、`miniprogram/shared`、云端 `lib` 各持一份注册表；生产新增运动必须走代码提交与镜像同步，不做运行时跨端下发。
- `meta` 标志必须由内核真实消费，不能只作装饰；P-03 已补 `defaultMatchTimeFromEvent`、`defaultDurationMinutes`、`supportsRankingDecisions`、`sharedEliminationRank` 的接线。
- 排球 `volleyball6` 尚未实现；新增排球时只需新增 `src/shared/sports/volleyball/` + registry 注册一行，不改内核。

- 跨运动规则隔离：篮球拒绝足球规则，足球拒绝篮球规则。
