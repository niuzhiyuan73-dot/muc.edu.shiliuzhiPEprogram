## 3 关键口径

1. **下推只覆盖能用索引表达的查询**。关键词是三个字段的包含匹配，云数据库没有可用于 contains 的索引，强行下推成正则等于全表扫描还绕过索引；年份要按东八区换算区间。这两条回退内存，数据量是「本协会赛事数」，不是全库。
2. **排序必须与内存版逐字同口径**。赛事：置顶 → 状态（0/1/2 与优先级一致）→ 开赛时间（`order` 决定方向）→ 编号升序；学院赛：置顶 → 状态（0..3）→ 开赛时间升序 → 编号。`_id` 兜底方向固定为升序，避免同一时刻的赛事在翻页时漂移。
3. **`total` 与 `totalAll` 分开计数**：前者是过滤后条数（分页基准），后者是「本协会一共多少场」（概况数字），后者不能被「只看报名中」的筛选带偏。
4. **积分榜的读量没有减少，只有传输与计算减少了**。积分是 `events + trainings + trainingRegistrations` 的运行时聚合，排名必须算完全量；要真正降读得把赛季积分物化到会员行，那是独立批次。
5. **`userIds` 批读不是选人候选**：上限 200，越界回业务拒绝。候选场景必须走分页（`page: true`）。

## 4 踩坑与纠正

- **计分台先取比赛、再按场批读人员，把「没权限」这条提示挤掉了**。原来的顺序是「先读名录，读不到就是没权限」，改成批读后必须先拿比赛才知道要读谁。用例当场红（未入会的人看到「比赛不存在」而不是「没有读取权限」）。修法是把 `getSchoolMatch` 的失败按文案分成两类：含「权限/会员」→ `blockReason`，其余 → `error`，两个位置各归其位。
- **契约测试拦住新增方法面**。`events` / `collegeEvents` 多了 `listPage`，`for-scope-contract` 立刻点名「方法面变了」——这正是它该做的事。同步期望时把理由写进注释，避免下次有人以为可以随手删。
- **`io.top` 原先没有 offset**。补参数时要同时改三处（云端适配器、内存 io、测试桩），少一处就是「本地能翻页、云端翻不动」。
