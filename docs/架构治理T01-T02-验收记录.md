## 3. 关键口径

1. **严格仿真写后读粒度（全局标志 → 按集合粒度 `writtenCollections`）**：
   - 旧口径：`txTracker.hasWritten` 全局布尔值，写过任意集合后拦截所有后续未缓存读取；
   - 新口径：改为 `txTracker.writtenCollections.has(key)` 按集合粒度校验——符合 CloudBase 快照隔离语义（允许事务内写集合 A 后读集合 B，但严禁同集合写后再读未缓存文档），同时倒逼清除了 9 处业务服务中同集合循环写后读遗漏。
2. **`cloud-repo.js` `doc.update` 兼容降级**：仅当桩对象存在 `ref.update` 函数时暴露 `update` 方法，兼容既有仅实现 `doc().set` 的极简测试桩。
3. **索引真值唯一化**：`config/db-indexes.json` 为唯一声明源，`docs/数据库索引清单.md` 第六节由 `npm run sync:indexes` 自动生成，`npm run check:indexes` / `deploy:check` 校验漂移。

---

## 4. 踩坑与纠正

1. **严苛仿真 36 个测试文件失败的真实归因**：
   - 初版用 `txTracker.hasWritten` 全局开关，将跨集合合法读写（如写 `associationTrainings` 后读 `seasons`）误判为违例，掩盖了真实问题；
   - 收口为按集合粒度后，暴露出并实锤修复了 9 处第二十三轮 Batch B 遗漏的同集合写后读不同 doc（`association-group-service`、`school-college-service` 3 处、`team-service`、`team-event-service`、`school-rating-service`、`meet-registration-service` 2 处、`school-event-service`、`season-points`），以及 `school-memory-repo` 中 `seasons.update` / `schoolMembers.update` 误触发 `read()` 计数的问题（云端 `doc.update` 并不先读）。
2. **`school-memory-repo` 重写时的接口兼容陷阱**：
   - `exchangeInvitations.listByScope` 委托 `forScope` 曾引发与 `school-repository` 之间的无限递归，已移除冗余覆盖；
   - `io.query` 仅在 scope-only 查询时走 `repo[key].list()`，既保留测试 `trackReads` / `team-event-p0` 的拦截钩子，又避免误触发 `football-f23` 对 `listByTeam` / `listByEvent` 的整表禁读断言。
