## 1. 复核目标

复核 P-01～P-04 的「已落地」结论是否名副实：插件主题是否有第二真值源、契约能否被非法插件绕过、声明的 meta 标志是否真的被内核读取、前端是否真正声明驱动（新运动无需改内核）、以及测试模块是否仍带伪插件接口。原则是**保留已跑通的服务端闭环，只补前端开闭与契约缺口**。

## 2. 改动清单

### P-01 主题单一真值与契约收紧
- 新增 `tools/gen-assoc-theme.js`：从 `src/shared/associations/` 插件的 `theme` 生成 `miniprogram/styles/assoc-theme.wxss`（文件头标 AUTO-GENERATED），`npm run gen:theme` / `npm run check:theme` 两个脚本；`deploy:check` 追加主题漂移检查。
- `miniprogram/app.wxss` 顶部 `@import "styles/assoc-theme.wxss"`，删除六套手抄 `.assoc-*` 块，只保留中性块；新增协会不再两处手抄。
- `src/shared/associations/base.js`：`validateAssociationPlugin` 收紧 `id` / `teamSportFormat` 格式（`/^[a-z][a-z0-9_]{1,31}$/`）、`capabilities` 去重、团队插件必须显式 `rulesKey` 且对应 `xxxRules` 非空对象；`teamRules()` 补 `rulesKey:'basketballRules'`，足球插件补 `rulesKey:'footballRules'`。
- `src/shared/associations/registry.js`：`registerAssociationPlugin` 增加 `sportKey` 全局唯一校验。
- `src/shared/sports/registry.js`：新增 `registerAssociationWithAdapter(plugin, adapter)`，适配器注册失败时回滚协会注册，消除半套状态。
- 新增 `tests/association-plugin-integrity.test.js`：遍历启用团队协会断言适配器非空、适配器格式至少对应一个协会（CI 守卫，不进生产启动路径）。
- `tests/associations.test.js` / `tests/association-plugin-registry.test.js` 主题一致性断言改读生成文件；三处动态插件夹具补 `rulesKey`。

### P-02 文档与读路径安全
- 新建 [P-02 验收记录](协会插件化P02-验收记录.md)，账本 P-02 行验收链接由设计文档改指本记录。
- [设计文档](团队运动-SportAdapter插件化设计方案.md)：状态由「待排球立项实施」改为「已实施（P-02/P-03）」；六组契约代码块、触发时机改为实际接口与已落地口径。
- `src/shared/sports/registry.js`：`getSportAdapterFor` 的 `normalizeRules` 抛错时安全返回 `null`，读路径不再 500。

### P-03 默认工厂与服务端白名单
- `src/shared/sports/contract.js`：默认 `initMatchExtra` 遵守 `defaultMatchTimeFromEvent`（false 时 `matchTime:null`）与 `defaultDurationMinutes`（函数时调用写入 `durationMinutes`）。
- `src/server/services/team-event-service.js`：结算时按 `supportsRankingDecisions` / `sharedEliminationRank` 分派，声明为 false 时忽略相应 payload / 保留原 placements；通用 `getTeamRecord` 返回体补 `sportFormat`。
- 新增 `src/server/sports/action-allowlist.js`：服务端插件动作统一白名单；`football-plugin.js` 改从该文件取名单；`server/sports/registry.js` 注册时校验每个 action 在白名单内且为函数。
- 新增 `tests/server-plugin-allowlist.test.js`；`sport-adapter-contract.test.js` 补默认钩子与 meta 分支断言。
- 账本 P-03「8 处调用点」口径修正为「7 处 + 1 处模块级动作分派包装」（`grep -c getSportAdapterFor` 实测为 7）。

### P-04 前端开闭补齐与伪插件收口
- `src/shared/sports/contract.js`：`rules.presetOptions`（`key`/`label` 非空、key 唯一）纳入校验；篮球适配器从 `RULE_PRESETS` 生成，虚拟排球适配器声明自己的 preset，足球留空走专属表单。

- `miniprogram/packageTeam/team-detail/team-detail.js`：`recordHintText` 取 `result.sportFormat` 并回退到协会适配器，不再只认返回值字段。
- `miniprogram/utils/team-profile-view.js`：未知非空 `sportFormat` 不再回落篮球（空列），仅旧数据空值时保留篮球兜底。
- `src/shared/sports/racket/registry.js`：移除动态 `registerScoringAdapter` / `unregisterScoringAdapter` 导出，ScoringAdapter 收口为内置 `point` / `tennis`；全仓无残留调用。
- `tests/plugin-open-closed-e2e.test.js`：静态守卫目标 `team-detail.wxml` 改为 `.js`，新增正向断言（建赛表单、统计列、`getTeamRecord.sportFormat`、档案视图按声明渲染、未知运动空列）；移除 fixture 中内核零引用的 `teamConfig`。
- 新增 `tests/team-event-form-view.test.js`、`tests/team-event-stat-view.test.js`。
- 三处测试夹具（`team-event-pages` / `frontend-explorer-bracket`）补 `sportFormat:'basketball5'` 以适配声明驱动。

## 4. 已知项与未完成

- **app-session 并发偶发失败（跳过深挖）**：`tests/app-session.test.js` 在多轮 `--concurrency 4/8` 全量中出现约 1/6～1/3 概率的单文件失败；该文件单独连跑 5 次、以及多数全量运行均通过。已把 `flush()` 加固为多跳以降低时序抖动，但复现时运行器只保留失败文件尾部 40 行、真实断言被截断，未定位到具体失败用例。按人工决定**不再深挖**，记录为已知项：该用例依赖模块级单例与 `launch()` 故意不 await 的 `refreshSession` 链，疑为并发高负载下的跨用例异步泄漏；后续若稳定复现，建议改用「等待启动 Promise 真正落定」而非固定跳数。当前交付以「常规全量 + 严苛仿真全量各一次全绿」为准，不把偶发失败当作已解决。
- **ScoringAdapter 收口为内置两种计分制**：`point` / `tennis` 已覆盖；动态注册接口移除。第三种计分制若要做需同时改 `match-format`、`match-record`、`live-score` 存储回放、`scheduledForm`，单列切片。
- **`teamConfig` 移除**：从开闭实证 fixture 与文档移除，内核零引用；如需 `teamMin/teamMax` 约束，单列切片在 team-service 建队/审批/加入路径读取。
- **服务端统计仍是篮球专用**：`saveTeamMatchStats` 仍只认篮球字段；新运动要真正保存统计需服务端插件覆写，本批只保证 UI 不再错误显示篮球列。
- **运行时动态注册的主题边界**：仅保证 `association-home` / `my-sports` 两个宿主页内联主题，不承诺动态协会全站换肤（那是生产插件 + `npm run gen:theme` 的路径）。
