## 3. 关键口径

1. **校级管理员不自助注销**：不采用“事务外统计最后一名管理员”——两人并发注销会同时放行。改为校级管理员一律不自助注销，必须交接或由平台管理员处理；将来若上线交接流程，再引入原子计数文档。
2. **T-04 保留 ≤6 项目逐项核对**：它不再是大届次的唯一防线，而是小届次的额外核对；大届次由 `entriesRevision`（报名面）+ `contentRevision`（发布面）+ `scheduleRevision`（赛程面）覆盖，事务操作数与项目数保持常数。
3. **昵称脱敏只在“昵称就是实名”时生效**：不改变注册默认昵称与用户自选昵称，避免破坏既有产品约定与种子数据。
4. **注销事务预算**：撤销一条运动会授权是读+写 2 次操作；在任授权超过 25 条时先要求人工交接，避免与 6 个协会会籍、账号/学籍/角色同事务时撞 100 次上限，退化成“服务异常”。
5. **历史验收记录冻结**：`docs/架构治理T01-T02-验收记录.md` 与 `T05` 记录中的 3343/结构缺口**不回写**；勘误只在本记录与账本追加行体现。

## 4. 踩坑与纠正

- **只读验收勘误**：初版本记录写 `g3-concurrency-batch` 为 14 条，实测为 13 条（开工基线 11 + 本批新增 2），已更正。新增的两条场景本身真实存在且断言到位，属数字笔误而非漏测。
- **`listDirectoryPage` 返回键是 `members` 不是 `rows`**：首版分页脱敏把 `rows` 当来源，覆盖成空数组，导致 3 条页面用例失败；改为优先读 `page.members` 后恢复。
- **UGC 测试的模块实例**：`handleSchoolRequest` 走云端镜像 `lib/server/services/ugc-safety.js`，测试里 `setUgcChecker` 改的是 `src` 实例；注册/团队赛事用例改用内置违禁词，避免“设了 checker 却不生效”的假绿。
- **球队只在团队项目存在**：匹克球（`pkb`）没有球队，注销退队夹具需用篮球（`bk`）；首版用 `pkb` 导致球队状态仍为 `active`。
- **G3 静态守卫正则**：`touchEvent` 从 `if (options && options.bumpMeet)` 改为 `const bumpMeet = Boolean(...)` 后，旧断言失效；已同步为门控变量断言，并新增 `bumpEntries` 断言。
