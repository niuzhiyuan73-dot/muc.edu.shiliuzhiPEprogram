## 3 关键口径

1. **按协会分键，而不是另开一张表**。会员行是学校级的（`sm:<school>:<user>`），赛季积分是「学校 × 协会」口径。分键后仍然是「读会员行顺带拿分」的零额外读；另开表会把读放大买回来。
2. **`update` 只能整字段替换**。map 必须用「事务内读到的当前行」构造再写回；用手上几百毫秒前的快照，卡在另一协会刚结算的窗口上就会把它那一格抹掉——这正是 P0 的机理。代价是每行多一次读，30 行会到 90 操作，所以批量降到 25。
3. **格式版本与代际分开**。代际回答「事实有没有变」，格式版本回答「这份数据是不是当前结构」。旧数据两条都可能满足第一条，只有格式版本能拦住它被当成有效值。
4. **失败即未结算**。行上「半新半旧」时对齐代际，等于告诉读端这份是准的；宁可退回实时聚合（慢，但对）。行被并发删掉（转出）不计失败：本来就没有可写对象。
5. **两协会互不清零**。判定「这条旧行要不要归零」时只看本协会那一格，别的协会的分与本协会无关。

## 4 踩坑与纠正

- **第一次注入写失败没打到点上**。`refreshAssociationPoints` 走的是事务内 `scoped.schoolMembers.update`（内部 `io.set`），不是顶层 `repo.schoolMembers.set`；补丁打在顶层时 `failed` 恒为 0，看起来「修好了」。改成拦 `repo.transaction` 才复现出 P1（`failed: 1` 仍 `settled: 1`）。
- **测试断言要跟着字段换**。`row.seasonPoints` / `row.pointsAnchor` 全部改为 map 取值；用正则按属性访问替换（`.seasonPoints` → `.seasonPointsByAssociation.pkb`），避免误伤模块变量 `seasonPoints`。
