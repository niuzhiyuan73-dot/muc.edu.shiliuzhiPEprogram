## 3. 关键口径

- 收尾以父运动会内容、赛程、生命周期三类版本保护快照，事件写入口必须同事务调用 `touchEvent`；新增父内容版本缺失按 0 兼容。
- 小组资格采用每人一条有效见证，不降低 30 人名单、20 组规模；见证失效时保守拒绝整单，用户刷新后重新选取。
- 轮询从“无限日预算”改为独立 12000 成本点/账号/实例/日，个人每场 1 点、团队每场 3 点。编号去重，最多计 50 场，空批量至少计 1 场。预算仍使用原实例内存机制，不是跨实例共享费用上限。
- 护照保留 `mtrow:<publicationKey>:<entryKey>` 排序键与卡片键，旧游标兼容；来源为当前发布快照，派生明细可滞后。
- 足球排期要求日期和时间，非法日历日拒绝；无时区按北京时间处理。

## 4. 踩坑与纠正

- 给所有项目和发布逐条加事务复核会继续触碰 100 操作预算；改为同事务维护父版本，同时补入派裁判的容量估算。
- 资格查询移出事务后不能只信旧结果，必须在事务内验证见证文档的学校、协会、用户、小组和 active 状态。
- 护照展开后若改用新排序键会影响在途游标，最终恢复原明细行主键形式，并加入精确断言。
- 仅验证“超限被拒绝”不能证明容量修好，本批必须同时让 50 项目、6/30 人乘 20 组的合法路径成功。
- 最终复核发现两种轮询对重复编号的处理顺序不同：团队先去重，个人先截取前 50 项。成本计算按各自真实读集合处理，并验证重复前缀不能少扣团队批量成本。
