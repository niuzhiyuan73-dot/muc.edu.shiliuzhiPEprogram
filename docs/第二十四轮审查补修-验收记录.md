## 3. 关键口径

- **重抽旧场次用物理删除**：这些场次都还没确认、没有结算与评级快照，留着只会被当成可开赛的真场次；确认过的场次在 `canRedraw` 已被拦住，因此不会删掉有结果的数据。
- **5–8 名排位做成可选项**：`placementMode=top8` 只在单败淘汰且建赛时显式开启才生效；关闭时签表与结算口径完全不变，历史赛事不受影响。名次以排位决赛结果为准，不再按「被淘汰轮次」倒排。
- **交手名额按比赛时间归属赛季**：从「驳回时用当前赛季」改为「用落库时的赛季戳」；历史记录无戳时保持旧行为，避免回填。
- **会员目录脏账号用「先隐藏、后迁移」**：从「抛错中断整页」改为「分页与计数都不算未回填账号」。旧行为下目录整页不可用且首页人数虚高；新口径下数字自洽，代价是未回填账号暂时不出现在名录里。
- **仓储 `remove` 只给草稿清理用**：归属校验在受范围层完成，顶层 `remove` 仅满足方法面，业务一律走 `forScope` / `forMeet`。

## 4. 踩坑与纠正

- 第 23 轮审查第 14 条「篮球单败未打完即可提前结算」经实测**不成立**：只打半决赛就结算会被「还没有产生可结算的名次」挡住。本批不是修这个伪缺陷，而是把提示口径统一成「还有未生成的淘汰赛程」。
- 原先假设「报名取消可造成重抽人数变少」，实测 `cancelSchoolEventSignup` 在赛事有 `draw` 后直接拒绝，因此正常操作路径造不出幽灵场。回归用例改为直接注入一条历史遗留场次，验证重抽会把它清掉；这覆盖的是数据修复能力，不是当前可复现的用户操作。
- 稳定指纹替换时首次脚本把 import 插在文件首行、且对 `Page(withDetailExperience({...}))` 这类包装写法找不到锚点，导致 7 个文件只改了方法体没有 import；已用通用 `Page(` 锚点补齐，语法检查与 393 条页面用例全绿。
- 契约测试两处钉住方法面的清单随新增 `remove` 更新（`for-scope-contract`、`meet-repo-contract`），不是放宽断言。

| 演示数据（约 150KB）迁入分包 | **不做（本批）** | 小程序分层是单向依赖：主包不能 require 分包，而 `school-identity` / `association-space` / `exchange` / `meet` 这些主包门面在 mock 模式下都要读种子。真正可迁的前提是先把演示模式整体做成一个自带页面的分包（门面注入数据源），属架构级改造。当前主包源码 3.0MB，演示数据只占约 5%，不是体积主因；现有惰性加载已保证云端模式不在启动时付这 400ms。 |
